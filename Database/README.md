# Jobmate database

PostgreSQL, schema `jobmate`. The schema is defined in C# and changed only through
**EF Core migrations**. [`schema.sql`](schema.sql) is a generated, read-only snapshot for
reviewing the whole schema in one place.

| Where | What |
|---|---|
| `src/Jobmate.Domain/Entities/` | Entity classes (PascalCase properties) |
| `src/Jobmate.Infrastructure/Persistence/Configurations/` | One `IEntityTypeConfiguration<T>` per entity: table, columns, indexes, relationships |
| `src/Jobmate.Infrastructure/Persistence/SchemaConventions.cs` | Naming rules applied to the whole model (PK/FK/index/check names, enum checks) |
| `src/Jobmate.Infrastructure/Persistence/Migrations/` | Migrations. EF records applied ones in `jobmate.__ef_migrations_history` |
| `tests/Jobmate.Infrastructure.Tests/Persistence/SchemaConventionTests.cs` | Fails the build if a rule below is broken or a model change has no migration |

## Naming rules

| Thing | Rule | Example |
|---|---|---|
| Table | snake_case, plural | `job_applications`, `saved_jobs` |
| Column | snake_case | `workers_needed`, `paid_at` |
| Primary key | `{singular table}_id`, `uuid` generated by the app | `job_application_id` |
| Foreign key column | the referenced key's name, with a role prefix when the role matters | `job_id`, `giver_user_id`, `reviewed_by_user_id` |
| Primary key constraint | `pk_{table}` | `pk_jobs` |
| Foreign key constraint | `fk_{table}_{column}` | `fk_jobs_giver_user_id` |
| Index | `ix_{table}_{what}` | `ix_verification_requests_user_type_status` |
| Unique index | `ux_{table}_{what}` | `ux_saved_jobs_user_job` |
| Check constraint | `chk_{table}_{what}` | `chk_payments_total_amount` |

C# properties stay PascalCase (`GiverId`); the configuration maps the column name.
PK, constraint and index names are set by `SchemaConventions`, so configurations never
spell them out.

## Every table has

- `created_at timestamptz NOT NULL` and `updated_at timestamptz NOT NULL`, stamped in UTC
  by `AppDbContext` on every save. No handler sets them.
- A `uuid` primary key.

## Soft delete

Only where users actually delete things: `jobs` (draft delete) and `saved_jobs` (unsave).
Those tables have `deleted_at timestamptz NULL`. A global query filter hides deleted
rows, and unique indexes on them carry `WHERE deleted_at IS NULL`.

Every other table keeps its history through its own `status` column (a job is
`Cancelled`, an application `Withdrawn`), so it never deletes rows.

## Integrity lives in the database

- **Every FK** is a real `REFERENCES` constraint with an index on the FK column.
- **Every enum column** is stored as its name (`'Active'`) and has a `chk_` constraint
  listing the allowed values. It is generated from the C# enum, so adding an enum value
  produces a migration automatically.
- **Business rules** are CHECKs or unique indexes where possible, e.g.
  `chk_payments_total_amount`, `chk_ratings_stars`, one application per worker per job.

## Types

| Data | Type |
|---|---|
| Timestamps | `timestamptz`, always UTC |
| Calendar date / time of day (a shift's date and start time) | `date` / `time` |
| Money | `integer`, whole rupees (currency in `payments.currency`). Keep new money columns consistent with this |
| Ratings / averages | `numeric(3,2)` |
| Coordinates | `double precision` |
| Flags | `boolean`, never `'Y'`/`'N'` |

## Changing the schema: checklist

1. Change the entity and its configuration (one place, no copy-paste).
2. Add a migration with a name that says what changed:
   ```powershell
   dotnet ef migrations add AddJobInvitations --project src/Jobmate.Infrastructure --startup-project src/Jobmate.Api --output-dir Persistence/Migrations
   ```
3. Read the generated `Up`/`Down`. If it drops or rewrites data, write the data step by
   hand in the migration and make sure `Down` can undo it.
4. New FKs get an index, new enum columns get their check automatically. Add CHECKs or
   unique indexes for any other rule.
5. Apply it to your dev database and refresh the snapshot:
   ```powershell
   dotnet ef database update --project src/Jobmate.Infrastructure --startup-project src/Jobmate.Api
   dotnet ef migrations script --project src/Jobmate.Infrastructure --startup-project src/Jobmate.Api -o Database/schema.sql
   ```
6. Run `dotnet test`. `SchemaConventionTests` checks the rules; the API tests migrate
   `jobmate_test` automatically.
7. Never edit a migration that has already been applied to a shared database. Add a new one.
